# The benchmark set

Three sources, fixed, so that a number taken today can be compared with one
taken in six months. Run them with `test/bench/bench.sh`.

| | what it is | why it is here |
|---|---|---|
| `bbcbasic` | BBC BASIC for Agon, 20 files, ~386 KB | The realistic one: deep includes, macros, and forward references that reach nearly the whole output |
| `rokky` | a smaller real program, ~25 KB | A different shape, and short enough to iterate on |
| `synth` | 471 KB generated by `gen_synth.sh` | Straight instructions, no labels, macros or includes, so it isolates lexing and encoding |

The first two live in `test/corpus`, vendored with the reference's test suite.
The third is generated deterministically -- the line at index *i* is a pure
function of *i*, with no randomness -- because 471 KB of nothing anyone needs to
read does not belong in a repository, but a benchmark whose input drifts is not
a benchmark.

**If `gen_synth.sh` ever changes, every timing taken before the change becomes
incomparable with every timing after it.** Add a new generator instead of
editing that one.

## How the timing is taken

The figure is **the assembler's own**. Both zap and ez80asm print
`Done in X.XX seconds`, and that is what the runner reports. Host wall clock is
not usable: it includes emulator startup, MOS boot and sdcard I/O, all of them
larger than the difference being measured.

The emulator runs **without `-u`**. Unthrottling decouples the guest's clock
from the work the guest does, so the number it prints stops meaning anything --
runs finish sooner and the results are worthless.

A source that prints no figure is reported as `-`, never as zero. A missing
figure means the program died, the emulator panicked, or the console output was
lost; treating it as a fast run would be worse than useless.

## Why not just profile on the host

Because the host disagrees with the target, in both directions and by a lot.
zap retires **0.71x** ez80asm's instructions under callgrind and takes **0.98x**
its time on an Agon. libc is vectorised on one machine and a byte loop on the
other, which flatters ez80asm's heavy `strcasecmp`/`strchr` use on the host;
meanwhile chasing struct pointers is cheap on x86 and expensive on a cacheless
eZ80 with 3-byte pointers, which flatters zap. The same gap has been seen the
other way round: the prescan single-scan change was 4.0% of host instructions
and 1.8% of target time.

Use callgrind to find *where* the work is. Use this to find out whether
removing it helped.

## Baseline

Recorded on fab-agon-emulator 1.2.4, zap at the commit that added this
directory. `RATIO` is zap divided by ez80asm, so lower is better and 0.50 is the
current goal.

See `BASELINE.md`, which is regenerated rather than edited by hand.

## isa_even and isa_real

Added because the rest of the set cannot answer "is this change good?" for
anything that touches instruction handling. `synth` and the pure file cycle a
few dozen hand-picked forms; between them they reach 31 of the ISA's 114
mnemonics and 40 of its 322 rows, with no `call`, `jp` or `djnz` at all.

`gen_isa.sh even` gives every one of the 1,083 forms dzap assembles the same
number of times, so nothing is over-weighted. `gen_isa.sh real` weights them by
how often each mnemonic appears in the two real programs already in
test/corpus -- BBC BASIC and Rokky, 10,440 instructions -- while still
containing every form at least once.

Why both: `even` says what the instruction set costs and cannot be gamed by a
change that helps common forms; `real` says what the assembler costs on the
source people actually write. A change that improves one and not the other is
worth understanding before taking.

They earned their place immediately. An operand-parsing change measured 1.5%
faster on the forty-form file, and 0.9% and 1.2% slower on these two.

Neither contains a relative jump. Without labels there is no way to write a
target that stays within a displacement's reach as the output grows, so `jr`
and `djnz` -- 10.3% of real instructions -- are covered by
`dzap/test/cases/relative.s` instead, and `real` is optimistic by about that
much.
